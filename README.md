# Historical quantile recentering under delayed audits

The final targeted diagnostics are in [`revisions/final-v1`](revisions/final-v1/README.md): both service partitions and both risk-selection regimes, daily risk tracking, Fixed-classwise matched-risk contrasts, complete second-partition service roles and class attribution. These are post-confirmation exploratory analyses. They retain the absence of a clear daily-variability advantage over Rolling global and the adverse second-partition outcomes. The original study and major revision remain in the commit history; earlier release manifests describe their own snapshots.

The post-confirmation supplementary revision is in [`revisions/major-v1`](revisions/major-v1/README.md). It adds zero-query Static HQR, risk curves, class/temporal analyses, a fixed sensitivity grid and a second service partition. All outcomes are retained, including the smaller second-partition gain with an interval crossing zero. These additions do not extend the original internal freeze retroactively.

The original study release remains at commit `e14d4847f56bc00524ee729952fb2d0e509d6e95`. The original reproduction route below is unchanged. The supplement guide provides both a lightweight table/figure route and staged full recomputation from the official data.


This study compares rejection calibration for a fixed encrypted-traffic classifier. Historical quantile recentering (HQR) applies established additive conditional-quantile score rectification to predicted-service groups, followed by a shared rolling quantile of delayed known-flow audit labels. 

The repository separates source fitting, historical calibration, development and frozen temporal confirmation. The original protocol is `research/frozen/confirmation-v1.json`, with a timestamped file-hash seal in `research/frozen/confirmation-v1-seal.json`. This was an internal analysis freeze, not an external preregistration. Scientific outputs have completion and independent arithmetic-audit receipts. A file ending in `preflight` or a test fixture is engineering evidence, not a reported effectiveness result.

## Two reproduction routes

The release includes the original derived confirmation estimates and source counts. To regenerate publication tables and figures without fitting models or downloading traffic, run these commands from the repository, replacing the absolute root path:

```bash
python scripts/build_result_tables.py --root /absolute/path/to/repository
python scripts/build_supplement.py
python scripts/plot_confirmation.py --root /absolute/path/to/repository
```

This route reproduces the reported presentation from retained observations; it is not a new independent experiment. The plotting environment must have NumPy and Matplotlib. The original numerical analysis used the experiment environment below.

For a complete new experiment, obtain the exact official XS HDF5 file and choose a new, separate work directory. Inspect the commands before allocating compute:

```bash
python scripts/run_reproduction.py --work-dir /absolute/path/to/new-rerun --plan
python scripts/run_reproduction.py --work-dir /absolute/path/to/new-rerun --data /absolute/path/to/CESNET-QUICEXT-25-XS.h5
```

The runner verifies the dataset checksum, copies the scientific implementation and configurations, links the data, trains the three source models, fits and audits historical mappings, executes and audits development comparisons, regenerates ACI selection, creates a new internal seal, evaluates confirmation and computes paired calendar-block estimates. Training requires three 50-epoch fits. The runner also supports the named stages printed by `--plan` for separately allocated environments. It refuses to overwrite an existing stage receipt; after a failure, inspect the retained files and failed command before taking further action.

Fresh reruns retain the published development rationale as provenance and generate their own numerical artifacts and seal. The original reported seal and completed results remain historical reference material in the repository. The 846 historical score-cache files bound by that original seal are not distributed here; they are regenerated by the complete-rerun route. Consequently, the published seal is not a shortcut for invoking confirmation in a partial source-only checkout. Use the runner's fresh work directory. The following sections describe the underlying individual commands.

Use the official CESNET-QUICEXT-25-XS HDF5 distribution. This data licence is distinct from the DataZoo software licence. Cite the dataset and its associated measurement paper. No payload reconstruction or new traffic collection is performed.

The exact XS file used here has 3,544,625,537 bytes and SHA256:


The full release has 10 million rows and 360 date tables. Place the file at `data/CESNET-QUICEXT-25-XS.h5` in a fresh study directory. The metadata inventory records field names, application codes, table names and row counts. Do not replace the official application labels with a new SNI taxonomy.

Temporal roles are source fitting (1–28 June 2024), historical calibration (29 June–7 July), development (8 July–30 September) and confirmation (1 October 2024–31 May 2025). Known-service selection uses source-period support only. Source sampling and calibration sampling remain fixed across model seeds. Distinct rows with identical packet prefixes are retained; input-overlap sensitivity is separate.

## Source fitting and historical mappings

All scripts accept an explicit project root. Use a fresh output tree; scientific stages refuse to overwrite completed or partial runs. For example:

```bash
python scripts/prepare.py --root /absolute/path/to/study --config configs/transformer-v1.json
python scripts/prepare.py --root /absolute/path/to/study --config configs/transformer-seed43-v1.json
python scripts/prepare.py --root /absolute/path/to/study --config configs/transformer-seed44-v1.json
```

These steps require the metadata inventory and official HDF5 file. They fit only on source rows, calibrate source feature geometry, and cache historical/development scores. They do not open confirmation flow tables. The source-row map must have the same hash for every model seed. Preparation checks the source date boundary and dataset version and records all flow tables read.

Historical mapping uses the fixed row-identity split: 14,875 known flows for mappings and 15,125 disjoint flows for initial risk calibration. The main HQR variants use the following configurations:


## Development evidence and freeze

The reference study retained all development comparisons and selected the simpler historical tail offset before confirmation. `research/verification/development-review.json` distinguishes daily-macro from period-macro findings. `research/verification/aci-selection.json` retains every declared ACI grid value and the selected step size for each score/budget/delay. `select_aci.py` regenerates that file from the retained development grid; its output was byte-identical to the original selection in a separate check. This portable selector was added after the internal freeze without changing the frozen selection. The development comparison scripts are `evaluate.py`, `audit.py`, `evaluate_aci.py` and `summarize_periods.py`. Their configurations specify source runs and identical audit streams.

`verify_confirmation_engine.py` checks delayed histories, numeric thresholds, cumulative ACI errors, calendar gaps, additive-map arithmetic and weighted bootstrap estimands on explicitly labelled engineering fixtures. Such fixtures never enter the manuscript results.

`freeze_confirmation.py` requires completed historical fits, map audits, development audits, the recorded selection and the confirmation preflight. It writes a new internal seal once and refuses to replace an existing one. A new independent reproduction should regenerate its own historical artifacts and internal seal in its fresh directory while keeping the published scientific settings. The original seal remains a historical record of the reported study; do not silently edit it to accommodate a changed implementation.

## Confirmation

The frozen confirmation is executable directly without the author's SSH configuration:

```bash
python scripts/score_confirmation.py --root /absolute/path/to/study --seed 42
python scripts/evaluate_confirmation.py --root /absolute/path/to/study --seed 42
```

Repeat for seeds 43 and 44, then run:

```bash
python scripts/analyse_confirmation.py --root /absolute/path/to/study
```

Scoring verifies the seal before opening confirmation flows and does not fit a model or mapping. Replay continues the July–September audit queue into confirmation, rather than restarting it in October. Budgets are 32/128/512 requested labels per day; delays are one/seven calendar days. Every requested unknown label consumes budget. Unknown labels never enter known-flow quantiles or ACI error updates. ACI uses the saved rejection at the original prediction time.

Every saved replay is independently checked against numeric order statistics, calendar-bounded feedback histories, common query costs and all true-class rejection counts. The original cached scores remain unchanged. Input-disjoint sensitivity retains the same thresholds and requests.

The main analysis recomputes period-level true-class macros and uses paired calendar blocks of 28 days, with 7/56-day sensitivity. Date weights are shared across every method, model and audit stream. Nine model/audit cells are fixed replications on the same traffic, not nine independent datasets. The analysis reports effect sizes and temporal bootstrap intervals without selecting a grid-wide winner.

## Outputs and figures

Each confirmation model has `score-complete.json`, `summary.csv` and `evaluation-complete.json`. The combined analysis has:

- `outputs/confirmation-analysis-v1/analysis.json`: primary estimates, paired intervals, per-model sensitivity and per-class rejection rates;
- `operating-grid.csv`: all frozen score/budget/delay/model/audit settings and both input views;
- `primary-daily-counts.jsonl.gz`: the source counts for primary result figures.

`plot_confirmation.py` reads these verified outputs, checks their hashes and renders editable PDF/SVG figures plus PNG previews. Display smoothing never enters the frozen statistical estimates. Every final figure requires actual visual inspection and a matching caption.

The public reproduction route does not require private transport settings, credentials or a lab scheduler. The raw dataset is obtained from its official distributor and is not redistributed with the code. Keep failed runs, repair reasons and any protocol amendments traceable.
