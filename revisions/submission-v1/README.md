# Submission-quality correction and offline reproduction

This release corrects exceedance-count interval reporting in supplementary Tables S24/S26/S28/S30. Historical `revisions/final-v1` files remain an audit baseline. Use the commands in this directory for the corrected submission tables.

The block bootstrap samples 243 calendar positions, including five missing dates. Effective observed-date weights vary by resample. Exceedance proportions already use the appropriate observed denominator; equivalent-day intervals now multiply each resampled proportion by 238. No interval is clipped. All point estimates, MAE, RMSE, p90 and exceedance proportions remain unchanged. These diagnostics are post-confirmation exploratory; the original frozen study is unchanged.

## Minimal runnable offline example

In a fresh clone of the public repository, use Python 3.12 and an isolated environment:

```bash
python -m pip install -r requirements-offline.txt
python revisions/submission-v1/scripts/run_offline_audit.py --work-dir /absolute/path/to/new-audit --plan
python revisions/submission-v1/scripts/run_offline_audit.py --work-dir /absolute/path/to/new-audit
```

Choose a new work directory. The driver refuses to overwrite existing work, verifies the public release manifest, copies only its listed public files and runs eight real steps. It reconstructs statistics from saved decisions, checks all daily-risk bootstrap draws, reproduces core paired/oracle intervals, regenerates original and supplementary tables, and recreates two result figures. It is not a new model-training experiment. Inspect `offline-audit-execution/execution.json` and each step's stdout/stderr in the new work directory.

The verified reference postprocessing runtime is Python 3.12.13, NumPy 2.5.4 and Matplotlib 3.11.2. NumPy and Matplotlib are the only numerical/plotting packages needed for this route. Training uses the separate root `requirements.txt` environment; do not treat it as the lightweight example.

## Inputs and expected outputs

- `results/offline-inputs/class-date-mean-counts.npz`: 60 real method/operating-point sufficient-statistic cubes. Class/date denominators are identical across the fixed computational cells; averaging numerators preserves the reported cell-average ratios. Metadata records the source hashes, both known sets, 1,417,414 unique flows and 238 observed dates.
- The earlier release's `primary-daily-counts.jsonl.gz`: original saved per-class decisions for all primary calibration methods. These are sufficient count records, not raw packet data.
- The earlier release's `daily-known-counts.csv`: actual daily known/rejected numerators for both partitions and both risk-selection regimes.
- `results/risk-tracking/summary.csv` and `paired-contrasts.csv`: corrected 192 summaries and 160 paired contrasts. `bootstrap-draws.npz` retains the shared weights, actual effective denominators and old/corrected draws for verification.
- `results/offline-reproduction`: regenerated two-partition primary outcomes, 7/28/56-day intervals, 28-day oracle checks and reconstructed service roles.
- `manuscript/tables/final-risk-*.tex`: corrected submission S23-S31 snippets. The historical final-v1 snippets are retained separately; they do not supersede this correction.
- Original/major/final figure-generation scripts retain their recorded inputs and output paths. Only the equivalent-day intervals require a new table; figure values are unchanged.

Calendar blocks preserve missing dates rather than compressing the timeline. Daily known FRR uses each date's actual known count. Nonlinear daily statistics are calculated within each fixed model/audit cell before averaging. Three model fits and three audit streams share the same traffic; they are not nine independent networks. Oracle matching is descriptive confirmation-based interpolation, not a deployable risk guarantee. Class-level intervals are exploratory and not family-wise adjusted.

## Individual commands and limits

`repair_risk_bootstrap.py` reproduces the old outputs before changing only fixed-scale count intervals. If the historical daily NPZ is absent in a public checkout, it reconstructs those exact integer arrays from the retained daily CSV. `verify_risk_repair.py` independently groups counts and directly expands calendar resamples for p90. `verify_offline_results.py` recomputes two-partition metrics and core intervals from the sufficient counts. `build_submission_tables.py` generates the corrected daily-risk tables.

Run these individual commands only in a fresh staged directory; result directories refuse overwriting. The driver above handles that staging. Files and scripts that mention `preflight` or `TEST_ONLY` are engineering checks, not effectiveness observations.

The offline route is CPU work, with no download or GPU requirement; actual durations are recorded by the driver. Full fitting requires extra compute and was not re-executed for this correction. This audit validates arithmetic and reporting conditional on stored decisions, not independent-network generalization. Adverse second-partition and rare-class results, unestablished original FRR noninferiority, and block-length sensitivity remain part of the study.
